## เริ่มต้นอย่างรวดเร็ว

วางข้อความนี้ลงในเอเจนต์เขียนโค้ดของคุณ:

```text
Install Rust Anything with npm i -g rust-anything, then run rust-anything setup. Run rust-anything go -- <slow command of this app> and finish the port until rust-anything gate passes.
```

หรือติดตั้งเอง:

```sh
cargo install rust-anything   # หรือ: npm install -g rust-anything
rust-anything setup           # เพิ่มเข้าไปใน Claude Code, Codex, Cursor, Gemini CLI และ OpenCode
rust-anything doctor          # ตรวจรันไทม์ที่โค้ดต้นฉบับของคุณต้องใช้ พร้อมวิธีแก้สำหรับแต่ละตัว
```

> [!WARNING]
> การบันทึกจะรันโค้ดจริงของต้นฉบับ ให้ทำงานบนสำเนา และชี้เซิร์ฟเวอร์ไปที่ฐานข้อมูลทดสอบ
> `record --sandbox` และ `app record --sandbox` รันโดยไม่มีเครือข่าย รีโปเป็นแบบอ่านอย่างเดียว และจำกัด CPU กับหน่วยความจำ (bubblewrap บน Linux, sandbox-exec บน macOS; `doctor` ตรวจว่ามีหรือไม่)

> [!TIP]
> **สำหรับเอเจนต์:** อ่าน [rustanything.ai/llms.txt](https://rustanything.ai/llms.txt) เพื่อดูขั้นตอนติดตั้ง คำสั่งทั้งหมด และขั้นตอนการพอร์ต

## วิธีการทำงาน

<p align="center">
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="assets/how-it-works/th-dark.svg">
    <img src="assets/how-it-works/th-light.svg" width="880" alt="analyze วางแผนว่าจะพอร์ตอะไร rust-anything go สร้างบริดจ์ บันทึก ให้เอเจนต์ของคุณพอร์ต และตรวจด้วย gate วนซ้ำจนทุกเคสที่บันทึกไว้ตรงกัน จากนั้น enable สลับการเรียกไปใช้ Rust">
  </picture>
</p>

**อะไรนับว่าเสร็จ** พฤติกรรม ไม่ใช่เทสต์ของคุณ `record` รันโค้ดต้นฉบับกับอินพุตที่สร้างขึ้นและอินพุตที่กำหนดให้ แล้วบันทึกสิ่งที่แต่ละการเรียกคืนค่า โยนออกมา และพิมพ์ออกมา การพอร์ตถือว่าเสร็จเมื่อ `gate` ผ่าน: ทุกเคสที่บันทึกไว้ตรงกัน และ fmt, clippy, `cargo test`, การตรวจ `unsafe`, การตรวจ stub และการตรวจว่ามีคำตอบที่บันทึกไว้ถูกแปะลงในโค้ดที่พอร์ตหรือไม่ ผ่านทั้งหมด เทสต์ของคุณเองก็รันด้วย

**เทสต์ของคุณกลายเป็นเคส** `record --from-tests -- npx jest` (หรือ `pytest`) รันชุดเทสต์ของต้นฉบับเอง และบันทึกทุกการเรียกที่ชุดเทสต์ทำกับยูนิต `--pin-clock` ตรึงนาฬิกาและตัวเลขสุ่มทั้งสองฝั่ง โค้ดที่ขึ้นกับวันที่จึงตรงกันได้

<p align="center">
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="assets/how-it-works-app-dark.svg">
    <img src="assets/how-it-works-app-light.svg" width="880" alt="การพอร์ตทั้งแอป: analyze วางแผน คุณเป็นคนตัดสินใจ app record บันทึกพฤติกรรมจริง front door รัน Rust ไว้หน้าต้นฉบับ ย้ายยูนิตมาทีละตัวจนไม่มีอะไรต้องย้อนกลับไปที่ต้นฉบับ แล้ว lift จะเหลือแอป Rust ล้วน">
  </picture>
</p>

**ทั้งแอป: CLI และเซิร์ฟเวอร์** `app record` บันทึก CLI (exit code, stdout, stderr, ไฟล์ที่เขียน) หรือเมื่อใช้ `--http` จะบันทึกคำตอบของเซิร์ฟเวอร์ต่อทุกคำขอ `app front-door` สร้างโครง `rust/app` ซึ่งเป็นไบนารี Rust ที่ถือจุดเริ่มต้นของโปรแกรม และส่งทุกอย่างที่ยังไม่ได้พอร์ตต่อให้ต้นฉบับ `app wire` ย้ายยูนิตมาทีละตัว `app replay` ต้องอยู่ที่ 100% ขณะที่อัตรา fallback ลดลงจนเป็นศูนย์ และ `app lift` จะเหลือแอป Rust ล้วน

**ผลข้างเคียงก็นับ** การพอร์ตที่ลืมส่ง webhook หรืออีเมลต้องไม่ผ่าน `app record --effects http,smtp` (หรือ `--effect-env WEBHOOK_URL=http-url`) ชี้แอปไปที่ตัวแทนในเครื่องที่บันทึกทุกการเรียกและอีเมลขาออก และ `--db-dump "sqlite3 app.db .dump"` บันทึกฐานข้อมูลหลังทุกคำขอ แล้ว replay จะตรวจว่าโค้ดที่พอร์ตทำแบบเดียวกัน

**ต้นฉบับยังเปลี่ยนอยู่เรื่อย ๆ?** `app drift` รันต้นฉบับซ้ำเทียบกับสิ่งที่บันทึกไว้ และแสดงรายการสิ่งที่ตอนนี้ตอบต่างไป ส่วน [GitHub Action](install.md#in-ci) รัน `gate` ทุกครั้งที่ push

**คุณเป็นคนตัดสินใจ** เมื่อคุณแก้พฤติกรรมของโค้ดที่พอร์ต `rules --add "<rule>"` จะเก็บไว้ และพรอมต์ของเอเจนต์ทุกครั้งหลังจากนั้นจะใส่มันด้วย ทุกอย่างที่ rust-anything เขียนอยู่ใน `<repo>/rust/`

**รายงานหรือย้ายจริง คุณเลือกได้** `analyze` และ `profile` แค่รายงาน: แผนที่จัดลำดับว่าควรพอร์ตอะไร และส่วนไหนร้อนที่สุดภายใต้งานจริง ทั้งสองเป็นคำสั่งธรรมดา รายงานจึงไม่เสียโทเค็นเลย `go` ย้ายทีละหนึ่งยูนิต: สร้างบริดจ์ให้ฟังก์ชันที่ร้อนที่สุด บันทึกมัน ส่งงานพอร์ตให้เอเจนต์ของคุณ จากนั้น build, diff และรัน `gate` แล้วเปิดใช้เฉพาะเมื่อทุกอย่างตรงกัน (TS/JS, Python และ PowerShell; `disable` ปิดกลับได้)

**การรันหนึ่งครั้งใช้เวลาแค่ไหน** การรัน `go` หนึ่งครั้งพอร์ตหนึ่งยูนิต โดยใช้เอเจนต์ไม่เกิน `--rounds` รอบ (ค่าเริ่มต้น 3): หนึ่งรอบสำหรับการพอร์ต แล้วอีกหนึ่งรอบต่อ diff หรือ gate ที่ไม่ผ่าน ทั้งแอปคือการรันหนึ่งครั้งต่อหนึ่งยูนิต คุณจึงหยุดหลังครั้งไหนก็ได้

**โมเดลราคาถูกสำหรับแผน โมเดลเก่งสำหรับการพอร์ต** แผนไม่ต้องใช้โมเดล สำหรับการพอร์ต ส่งคำสั่งเอเจนต์อะไรก็ได้: `rust-anything go --agent "claude --model <model>" -- <workload>`

**เอเจนต์** `rust-anything setup` เพิ่มเข้าไปใน Claude Code, Codex, Cursor, Gemini CLI และ OpenCode ไคลเอนต์ MCP อื่นใดก็รัน `rust-anything mcp` ได้ และสกิลยังติดตั้งแยกได้ด้วย `npx skills add erkamyaman/rust-anything` (ดู[การติดตั้ง](install.md))

## คำสั่ง

| คำสั่ง | ทำอะไร |
| --- | --- |
| `rust-anything go -- <workload>` | โปรไฟล์ สร้างบริดจ์ให้ฟังก์ชันที่ร้อนที่สุด บันทึก ส่งงานพอร์ตให้เอเจนต์ของคุณ รัน gate แล้วเปิดใช้ |
| `rust-anything analyze <repo>` | แผนย้ายที่จัดลำดับแล้ว: ยูนิต ความพร้อม ความเสี่ยง dependency |
| `rust-anything profile <repo> -- <workload>` | ส่วนไหนร้อนภายใต้งานจริง และอะไรควรพอร์ตหรือรวมเป็นชุด |
| `rust-anything bridge <repo> <unit>` | crate ของ Rust พร้อม binding สำหรับหนึ่งยูนิต และ stub ใน `src/port.rs` |
| `rust-anything record <crate>` | บันทึกสิ่งที่ต้นฉบับคืนค่า โยนออกมา และพิมพ์ออกมา (`--inputs`, `--from-tests`, `--pin-clock`) |
| `rust-anything diff <crate>` | รันทุกเคสที่บันทึกไว้ซ้ำกับโมดูล Rust |
| `rust-anything bench <crate>` | จับเวลาต้นฉบับและ Rust บนเคสที่บันทึกไว้ รวมบริดจ์ด้วย |
| `rust-anything fuzz <crate>` | อินพุตใหม่ผ่านทั้งสองฝั่ง: สิ่งที่การบันทึกไม่ได้ครอบคลุม |
| `rust-anything gate <crate>` | นิยามของคำว่าเสร็จ |
| `rust-anything enable` / `disable <crate>` | สลับผู้เรียกไปใช้ Rust หรือสลับกลับ |
| `rust-anything report <crate>` | `REPORT.md` และการ์ดสำหรับ pull request |
| `rust-anything app record` / `front-door` / `wire` / `replay` / `lift` / `drift` | พอร์ตทั้ง CLI หรือทั้งเซิร์ฟเวอร์ |
| `rust-anything rules <repo> --add "<rule>"` | พฤติกรรมที่คุณแก้ไว้ ถูกเก็บไว้ในการพอร์ตทุกครั้งหลังจากนั้น |
| `rust-anything map <repo>` | ทุกยูนิต พร้อม crate เคส และ diff ล่าสุด |
| `rust-anything log <repo>` | ทุกการเปิดหรือปิด และผลของ wire, lift และ gate ทุกครั้ง จาก `rust/audit.jsonl` |
