## त्वरित शुरुआत

इसे अपने कोडिंग एजेंट में पेस्ट करें:

```text
Install Rust Anything with npm i -g rust-anything, then run rust-anything setup. Run rust-anything go -- <slow command of this app> and finish the port until rust-anything gate passes.
```

या इसे खुद इंस्टॉल करें:

```sh
cargo install rust-anything   # या: npm install -g rust-anything
rust-anything setup           # इसे Claude Code, Codex, Cursor, Gemini CLI और OpenCode में जोड़ता है
rust-anything doctor          # आपके मूल कोड को जिन रनटाइम की ज़रूरत है उन्हें जाँचता है, हर एक का समाधान भी बताता है
```

> [!WARNING]
> रिकॉर्डिंग मूल कोड को सच में चलाती है। एक कॉपी पर काम करें, और सर्वर को टेस्ट डेटाबेस से जोड़ें।
> `record --sandbox` और `app record --sandbox` इसे बिना नेटवर्क, रिपॉज़िटरी को सिर्फ़ पढ़ने लायक रखकर और CPU व मेमोरी की सीमाओं के साथ चलाते हैं (Linux पर bubblewrap, macOS पर sandbox-exec; `doctor` इसकी जाँच करता है)।

> [!TIP]
> **एजेंट:** इंस्टॉल के चरण, सभी कमांड और पोर्टिंग का तरीका जानने के लिए [rustanything.ai/llms.txt](https://rustanything.ai/llms.txt) पढ़ें।

## यह कैसे काम करता है

<p align="center">
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="assets/how-it-works/hi-dark.svg">
    <img src="assets/how-it-works/hi-light.svg" width="880" alt="analyze योजना बनाता है कि क्या पोर्ट करना है; rust-anything go ब्रिज बनाता है, रिकॉर्ड करता है, आपके एजेंट से पोर्ट करवाता है और gate से जाँचता है, तब तक दोहराता है जब तक रिकॉर्ड किया गया हर केस मेल न खाए; फिर enable कॉल को Rust पर स्विच करता है">
  </picture>
</p>

**किसे पूरा माना जाता है।** व्यवहार, आपके टेस्ट नहीं। `record` मूल कोड को जनरेट किए गए और दिए गए इनपुट पर चलाता है, और हर कॉल जो लौटाती है, फेंकती है और प्रिंट करती है, उसे सहेजता है। पोर्ट तब पूरा होता है जब `gate` पास हो जाए: रिकॉर्ड किया गया हर केस मेल खाता है, और fmt, clippy, `cargo test`, `unsafe` जाँच, स्टब जाँच और पोर्ट में चिपकाए गए रिकॉर्ड किए गए जवाबों की जाँच, सब पास होते हैं। आपके अपने टेस्ट भी चलते हैं।

**आपके टेस्ट केस बन जाते हैं।** `record --from-tests -- npx jest` (या `pytest`) मूल कोड का अपना टेस्ट सूट चलाता है और यूनिट को की गई हर कॉल रिकॉर्ड करता है। `--pin-clock` दोनों तरफ़ घड़ी और रैंडम नंबर तय कर देता है, ताकि तारीख़ पर निर्भर कोड भी मेल खा सके।

<p align="center">
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="assets/how-it-works-app-dark.svg">
    <img src="assets/how-it-works-app-light.svg" width="880" alt="पूरे ऐप को पोर्ट करना: analyze योजना बनाता है, फ़ैसले आप करते हैं, app record उसका असली व्यवहार रिकॉर्ड करता है, front door मूल कोड के आगे Rust चलाता है, यूनिट एक-एक करके आते हैं जब तक कुछ भी मूल कोड पर वापस न जाए, फिर lift एक शुद्ध Rust ऐप छोड़ता है">
  </picture>
</p>

**पूरे ऐप: CLI और सर्वर।** `app record` एक CLI (exit code, stdout, stderr, लिखी गई फ़ाइलें) को रिकॉर्ड करता है, या `--http` के साथ हर रिक्वेस्ट पर सर्वर के जवाब। `app front-door` `rust/app` बनाता है, एक Rust बाइनरी जो एंट्री पॉइंट संभालती है और जो कुछ अभी पोर्ट नहीं हुआ वह सब मूल कोड को सौंप देती है। `app wire` यूनिटों को एक-एक करके ले आता है, fallback दर शून्य तक गिरने के दौरान `app replay` को 100% पर रहना होता है, और `app lift` एक शुद्ध Rust ऐप छोड़ता है।

**साइड इफ़ेक्ट भी गिने जाते हैं।** जो पोर्ट webhook या ईमेल भेजना भूल जाए, उसे फ़ेल होना चाहिए। `app record --effects http,smtp` (या `--effect-env WEBHOOK_URL=http-url`) ऐप को ऐसे लोकल विकल्पों की ओर मोड़ता है जो हर बाहर जाने वाली कॉल और मेल रिकॉर्ड करते हैं, और `--db-dump "sqlite3 app.db .dump"` हर रिक्वेस्ट के बाद डेटाबेस रिकॉर्ड करता है; replay जाँचता है कि पोर्ट भी वही करता है।

**मूल कोड बदलता रहता है?** `app drift` मूल कोड को उसकी रिकॉर्डिंग के सामने फिर से चलाता है और बताता है कि अब क्या अलग जवाब देता है, और [GitHub Action](install.md#in-ci) हर push पर `gate` चलाता है।

**फ़ैसले आप करते हैं।** जब आप पोर्ट का व्यवहार सुधारते हैं, तो `rules --add "<rule>"` उसे सहेज लेता है, और बाद का हर एजेंट प्रॉम्प्ट उसे शामिल करता है। rust-anything जो कुछ लिखता है, वह सब `<repo>/rust/` में रहता है।

**रिपोर्ट या माइग्रेशन, आप चुनें।** `analyze` और `profile` सिर्फ़ रिपोर्ट करते हैं: क्या पोर्ट करना है उसकी प्राथमिकता के क्रम में योजना, और असली वर्कलोड में कौन सा हिस्सा सबसे ज़्यादा समय लेता है। ये साधारण कमांड हैं, इसलिए रिपोर्ट में कोई टोकन खर्च नहीं होता। `go` एक यूनिट माइग्रेट करता है: सबसे ज़्यादा समय लेने वाले फ़ंक्शन के लिए ब्रिज बनाता है, उसे रिकॉर्ड करता है, पोर्ट आपके एजेंट को सौंपता है, फिर उसे बिल्ड करता है, diff करता है और `gate` से गुज़ारता है, और सब कुछ मेल खाने पर ही उसे चालू करता है (TS/JS, Python और PowerShell; `disable` उसे फिर से बंद करता है)।

**एक रन में कितना समय लगता है।** एक `go` रन एक यूनिट पोर्ट करता है, ज़्यादा से ज़्यादा `--rounds` एजेंट टर्न में (डिफ़ॉल्ट 3): एक पोर्ट के लिए, फिर हर फ़ेल हुए diff या gate के लिए एक। पूरा ऐप हर यूनिट के लिए एक रन है, इसलिए आप किसी भी रन के बाद रुक सकते हैं।

**योजना के लिए सस्ता मॉडल, पोर्ट के लिए मज़बूत मॉडल।** योजना को किसी मॉडल की ज़रूरत नहीं। पोर्ट के लिए कोई भी एजेंट कमांड दें: `rust-anything go --agent "claude --model <model>" -- <workload>`।

**एजेंट।** `rust-anything setup` इसे Claude Code, Codex, Cursor, Gemini CLI और OpenCode में जोड़ता है। कोई भी दूसरा MCP क्लाइंट `rust-anything mcp` चला सकता है, और स्किल `npx skills add erkamyaman/rust-anything` से अलग से भी इंस्टॉल होती है ([इंस्टॉल](install.md) देखें)।

| कमांड | क्या करता है |
| --- | --- |
| `rust-anything go -- <workload>` | प्रोफ़ाइल करता है, सबसे ज़्यादा समय लेने वाले फ़ंक्शन का ब्रिज बनाता है, उसे रिकॉर्ड करता है, पोर्ट आपके एजेंट को सौंपता है, gate से गुज़ारता है, चालू करता है |

| `rust-anything profile <repo> -- <workload>` | असली वर्कलोड में कौन सा हिस्सा सबसे ज़्यादा समय लेता है, और क्या पोर्ट या बैच करना है |
| `rust-anything bridge <repo> <unit>` | एक यूनिट के लिए बाइंडिंग वाला Rust crate, स्टब `src/port.rs` में |
| `rust-anything record <crate>` | मूल कोड जो लौटाता है, फेंकता है और प्रिंट करता है उसे रिकॉर्ड करता है (`--inputs`, `--from-tests`, `--pin-clock`) |
| `rust-anything diff <crate>` | रिकॉर्ड किया गया हर केस Rust मॉड्यूल के सामने फिर से चलाता है |
| `rust-anything bench <crate>` | रिकॉर्ड किए गए केस पर मूल कोड और Rust का समय मापता है, ब्रिज समेत |
| `rust-anything fuzz <crate>` | दोनों तरफ़ नए इनपुट: जो रिकॉर्डिंग में नहीं आया |
| `rust-anything gate <crate>` | पूरा होने की परिभाषा |
| `rust-anything enable` / `disable <crate>` | कॉल करने वालों को Rust पर ले जाता है, या वापस |
| `rust-anything report <crate>` | `REPORT.md` और pull request के लिए एक कार्ड |
| `rust-anything app record` / `front-door` / `wire` / `replay` / `lift` / `drift` | पूरी CLI या सर्वर पोर्ट करता है |
| `rust-anything rules <repo> --add "<rule>"` | आपका सुधारा हुआ व्यवहार, बाद के हर पोर्ट में रखा जाता है |
| `rust-anything map <repo>` | हर यूनिट, उसका crate, केस और आख़िरी diff |
| `rust-anything log <repo>` | हर चालू या बंद करना, हर wire, lift और gate नतीजा, `rust/audit.jsonl` से |
