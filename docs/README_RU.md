## Быстрый старт

Вставьте это в своего агента для кода:

```text
Install Rust Anything with npm i -g rust-anything, then run rust-anything setup. Run rust-anything go -- <slow command of this app> and finish the port until rust-anything gate passes.
```

Или установите сами:

```sh
cargo install rust-anything   # или: npm install -g rust-anything
rust-anything setup           # добавляет его в Claude Code, Codex, Cursor, Gemini CLI и OpenCode
rust-anything doctor          # проверяет среды выполнения, нужные вашему оригиналу, и для каждой даёт исправление
```

> [!WARNING]
> Запись запускает настоящий код оригинала. Работайте с копией и направляйте сервер на тестовую базу данных.
> `record --sandbox` и `app record --sandbox` запускают его без сети, с репозиторием только для чтения и с ограничениями CPU и памяти (bubblewrap в Linux, sandbox-exec в macOS; `doctor` проверяет, есть ли он).

> [!TIP]
> **Агентам:** прочитайте [rustanything.ai/llms.txt](https://rustanything.ai/llms.txt), там шаги установки, все команды и порядок портирования.

## Как это работает

<p align="center">
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="assets/how-it-works/ru-dark.svg">
    <img src="assets/how-it-works/ru-light.svg" width="880" alt="analyze планирует, что портировать; rust-anything go строит мост, записывает, отдаёт порт вашему агенту и прогоняет через gate, повторяя, пока каждый записанный случай не совпадёт; затем enable переключает вызовы на Rust">
  </picture>
</p>

**Что считается готовым.** Поведение, а не ваши тесты. `record` запускает оригинал на сгенерированных и заданных входных данных и сохраняет, что каждый вызов возвращает, выбрасывает и печатает. Порт готов, когда проходит `gate`: каждый записанный случай совпадает, а fmt, clippy, `cargo test`, проверка `unsafe`, проверка заглушек и проверка на записанные ответы, вставленные в порт, тоже проходят. Ваши собственные тесты тоже запускаются.

**Ваши тесты становятся случаями.** `record --from-tests -- npx jest` (или `pytest`) запускает собственный набор тестов оригинала и записывает каждый вызов, который он делает к модулю. `--pin-clock` фиксирует часы и случайные числа на обеих сторонах, так что код, зависящий от даты, тоже может совпасть.

<p align="center">
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="assets/how-it-works-app-dark.svg">
    <img src="assets/how-it-works-app-light.svg" width="880" alt="Перенос целого приложения: analyze его планирует, решения принимаете вы, app record записывает его реальное поведение, front door запускает Rust перед оригиналом, модули переходят по одному, пока ничего не уходит обратно к оригиналу, затем lift оставляет чистое приложение на Rust">
  </picture>
</p>

**Целые приложения: CLI и серверы.** `app record` записывает CLI (код выхода, stdout, stderr, записанные файлы) или, с `--http`, ответы сервера на каждый запрос. `app front-door` создаёт `rust/app`, бинарник на Rust, который берёт на себя точку входа и передаёт оригиналу всё, что ещё не портировано. `app wire` переносит модули по одному, `app replay` должен держаться на 100%, пока доля fallback падает до нуля, а `app lift` оставляет чистое приложение на Rust.

**Побочные эффекты тоже считаются.** Порт, который забывает отправить вебхук или письмо, должен провалиться. `app record --effects http,smtp` (или `--effect-env WEBHOOK_URL=http-url`) направляет приложение на локальные подставные сервисы, которые записывают каждый исходящий вызов и письмо, а `--db-dump "sqlite3 app.db .dump"` записывает базу данных после каждого запроса; replay проверяет, что порт делает то же самое.

**Оригинал продолжает меняться?** `app drift` прогоняет оригинал против его записи и перечисляет, что теперь отвечает иначе, а [GitHub Action](install.md#in-ci) запускает `gate` при каждом push.

**Решаете вы.** Когда вы исправляете поведение порта, `rules --add "<rule>"` сохраняет это, и каждый следующий промпт агента это включает. Всё, что пишет rust-anything, лежит в `<repo>/rust/`.

**Отчёт или миграция, выбирать вам.** `analyze` и `profile` только сообщают: ранжированный план того, что портировать, и что горячее всего под реальной нагрузкой. Это обычные команды, поэтому отчёт не тратит токенов. `go` переносит один модуль: строит мост к самой горячей функции, записывает её, передаёт порт вашему агенту, затем собирает, сравнивает и прогоняет через `gate`, и включает его, только когда всё совпадает (TS/JS, Python и PowerShell; `disable` выключает обратно).

**Сколько длится запуск.** Один запуск `go` портирует один модуль, максимум за `--rounds` ходов агента (по умолчанию 3): один на порт, затем по одному на каждый непройденный diff или gate. Целое приложение переносится по одному запуску на модуль, так что можно остановиться после любого из них.

**Дешёвая модель для плана, сильная для порта.** Плану модель не нужна. Для порта передайте любую команду агента: `rust-anything go --agent "claude --model <model>" -- <workload>`.

**Агенты.** `rust-anything setup` добавляет его в Claude Code, Codex, Cursor, Gemini CLI и OpenCode. Любой другой MCP-клиент может запустить `rust-anything mcp`, а навык также ставится отдельно через `npx skills add erkamyaman/rust-anything` (см. [установку](install.md)).

## Команды

| Команда | Что делает |
| --- | --- |
| `rust-anything go -- <workload>` | Профилирует, строит мост к самой горячей функции, записывает её, передаёт порт вашему агенту, прогоняет через gate, включает |
| `rust-anything analyze <repo>` | Ранжированный план миграции: модули, готовность, риски, зависимости |
| `rust-anything profile <repo> -- <workload>` | Что горячее всего под реальной нагрузкой, и что портировать или объединять в пакеты |
| `rust-anything bridge <repo> <unit>` | Rust-крейт с привязками для одного модуля, заглушки в `src/port.rs` |
| `rust-anything record <crate>` | Записывает, что оригинал возвращает, выбрасывает и печатает (`--inputs`, `--from-tests`, `--pin-clock`) |
| `rust-anything diff <crate>` | Прогоняет каждый записанный случай против модуля на Rust |
| `rust-anything bench <crate>` | Замеряет время оригинала и Rust на записанных случаях, включая мост |
| `rust-anything fuzz <crate>` | Свежие входные данные через обе стороны: то, чего не покрыла запись |
| `rust-anything gate <crate>` | Определение готовности |
| `rust-anything enable` / `disable <crate>` | Переключает вызывающий код на Rust или обратно |
| `rust-anything report <crate>` | `REPORT.md` и карточка для pull request |
| `rust-anything app record` / `front-door` / `wire` / `replay` / `lift` / `drift` | Портирует целый CLI или сервер |
| `rust-anything rules <repo> --add "<rule>"` | Исправленное вами поведение, которое сохраняет каждый следующий порт |
| `rust-anything map <repo>` | Каждый модуль, его крейт, случаи и последний diff |
| `rust-anything log <repo>` | Каждое включение или выключение, каждый результат wire, lift и gate, из `rust/audit.jsonl` |
| `rust-anything setup` / `doctor` / `mcp` | Установка для агентов, проверка сред выполнения, MCP-сервер |
