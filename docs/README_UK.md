## Швидкий старт

Вставте це у свого агента для коду:

```text
Install Rust Anything with npm i -g rust-anything, then run rust-anything setup. Run rust-anything go -- <slow command of this app> and finish the port until rust-anything gate passes.
```

Або встановіть самі:

```sh
cargo install rust-anything   # або: npm install -g rust-anything
rust-anything setup           # додає його до Claude Code, Codex, Cursor, Gemini CLI і OpenCode
rust-anything doctor          # перевіряє середовища виконання, потрібні вашому оригіналу, і для кожного дає виправлення
```

> [!WARNING]
> Запис запускає справжній код оригіналу. Працюйте з копією і спрямовуйте сервер на тестову базу даних.
> `record --sandbox` і `app record --sandbox` запускають його без мережі, з репозиторієм лише для читання і з обмеженнями CPU та пам'яті (bubblewrap у Linux, sandbox-exec у macOS; `doctor` перевіряє, чи він є).

> [!TIP]
> **Агентам:** прочитайте [rustanything.ai/llms.txt](https://rustanything.ai/llms.txt), там кроки встановлення, усі команди й порядок портування.

## Як це працює

<p align="center">
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="assets/how-it-works/uk-dark.svg">
    <img src="assets/how-it-works/uk-light.svg" width="880" alt="analyze планує, що портувати; rust-anything go будує міст, записує, передає порт вашому агенту і проганяє через gate, повторюючи, доки кожен записаний випадок не збігатиметься; потім enable перемикає виклики на Rust">
  </picture>
</p>

**Що вважається готовим.** Поведінка, а не ваші тести. `record` запускає оригінал на згенерованих і заданих вхідних даних і зберігає, що кожен виклик повертає, викидає і друкує. Порт готовий, коли проходить `gate`: кожен записаний випадок збігається, а fmt, clippy, `cargo test`, перевірка `unsafe`, перевірка заглушок і перевірка на записані відповіді, вставлені в порт, теж проходять. Ваші власні тести теж запускаються.

**Ваші тести стають випадками.** `record --from-tests -- npx jest` (або `pytest`) запускає власний набір тестів оригіналу і записує кожен виклик, який він робить до модуля. `--pin-clock` фіксує годинник і випадкові числа з обох боків, тож код, що залежить від дати, теж може збігтися.

<p align="center">
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="assets/how-it-works-app-dark.svg">
    <img src="assets/how-it-works-app-light.svg" width="880" alt="Перенесення цілого застосунку: analyze його планує, рішення ухвалюєте ви, app record записує його реальну поведінку, front door запускає Rust перед оригіналом, модулі переходять по одному, доки ніщо не повертається до оригіналу, потім lift залишає чистий застосунок на Rust">
  </picture>
</p>

**Цілі застосунки: CLI і сервери.** `app record` записує CLI (код виходу, stdout, stderr, записані файли) або, з `--http`, відповіді сервера на кожен запит. `app front-door` створює `rust/app`, бінарник на Rust, який бере на себе точку входу і передає оригіналу все, що ще не портовано. `app wire` переносить модулі по одному, `app replay` має триматися на 100%, поки частка fallback падає до нуля, а `app lift` залишає чистий застосунок на Rust.

**Побічні ефекти теж рахуються.** Порт, який забуває надіслати вебхук чи лист, має провалитися. `app record --effects http,smtp` (або `--effect-env WEBHOOK_URL=http-url`) спрямовує застосунок на локальні підставні сервіси, які записують кожен вихідний виклик і лист, а `--db-dump "sqlite3 app.db .dump"` записує базу даних після кожного запиту; replay перевіряє, що порт робить те саме.

**Оригінал і далі змінюється?** `app drift` проганяє оригінал проти його запису і перелічує, що тепер відповідає інакше, а [GitHub Action](install.md#in-ci) запускає `gate` при кожному push.

**Вирішуєте ви.** Коли ви виправляєте поведінку порту, `rules --add "<rule>"` зберігає це, і кожен наступний промпт агента це містить. Усе, що пише rust-anything, лежить у `<repo>/rust/`.

**Звіт чи міграція, вирішувати вам.** `analyze` і `profile` лише звітують: упорядкований план того, що портувати, і що найгарячіше під реальним навантаженням. Це звичайні команди, тож звіт не витрачає токенів. `go` переносить один модуль: будує міст до найгарячішої функції, записує її, передає порт вашому агенту, потім збирає, порівнює і проганяє через `gate`, і вмикає його лише тоді, коли все збігається (TS/JS, Python і PowerShell; `disable` вимикає назад).

**Скільки триває запуск.** Один запуск `go` портує один модуль, щонайбільше за `--rounds` ходів агента (типово 3): один на порт, потім по одному на кожен непройдений diff чи gate. Цілий застосунок переноситься по одному запуску на модуль, тож можна зупинитися після будь-якого з них.

**Дешева модель для плану, сильна для порту.** Плану модель не потрібна. Для порту передайте будь-яку команду агента: `rust-anything go --agent "claude --model <model>" -- <workload>`.

**Агенти.** `rust-anything setup` додає його до Claude Code, Codex, Cursor, Gemini CLI і OpenCode. Будь-який інший MCP-клієнт може запустити `rust-anything mcp`, а навичка також встановлюється окремо через `npx skills add erkamyaman/rust-anything` (див. [встановлення](install.md)).

| Мова | Статус | На чому перевірено |
| --- | --- | --- |
| TypeScript/JavaScript | Підтверджено | ESLint, Prettier, json-server, Fuse.js, vercel/ms |
| Python | Підтверджено | `colorsys` із CPython (2,400/2,400 випадків) |
| Go | Підтверджено | `path` із Go (2,642/2,642) |
| Ruby | Підтверджено | `shellwords` із Ruby 3.3 (1,617/1,617) |
| Java | Підтверджено | JDK 21 за фасадом (4,492/4,492) |
| C | Підтверджено | libavutil із ffmpeg, glibc |
| C# | Підтверджено | Google.Protobuf (2,941/2,941) |
| PHP | Підтверджено | PEAR `XML_Util` (1,838/1,838) |
| Kotlin | Протестовано | фікстури цього репозиторію, включно з Android |
| PowerShell | Протестовано | фікстури цього репозиторію |
| Swift | Протестовано | фікстури цього репозиторію |

**Підтверджено** означає портовано повністю на реальному коді, який написав хтось інший; **Протестовано** означає покрито тестами цього репозиторію на фікстурах. Усі запуски, з датами і способом перевірки: [STATUS.md](STATUS.md).

## Команди

| Команда | Що робить |
| --- | --- |
| `rust-anything go -- <workload>` | Профілює, будує міст до найгарячішої функції, записує її, передає порт вашому агенту, проганяє через gate, вмикає |
| `rust-anything analyze <repo>` | Упорядкований план міграції: модулі, готовність, ризики, залежності |
| `rust-anything profile <repo> -- <workload>` | Що найгарячіше під реальним навантаженням, і що портувати або об'єднувати в пакети |
| `rust-anything bridge <repo> <unit>` | Rust-крейт із прив'язками для одного модуля, заглушки в `src/port.rs` |
| `rust-anything record <crate>` | Записує, що оригінал повертає, викидає і друкує (`--inputs`, `--from-tests`, `--pin-clock`) |
| `rust-anything diff <crate>` | Проганяє кожен записаний випадок проти модуля на Rust |
| `rust-anything bench <crate>` | Вимірює час оригіналу і Rust на записаних випадках, разом із мостом |
| `rust-anything fuzz <crate>` | Свіжі вхідні дані через обидва боки: те, чого не покрив запис |
| `rust-anything gate <crate>` | Визначення готовності |
| `rust-anything enable` / `disable <crate>` | Перемикає код, що викликає, на Rust або назад |
| `rust-anything report <crate>` | `REPORT.md` і картка для pull request |
| `rust-anything app record` / `front-door` / `wire` / `replay` / `lift` / `drift` | Портує цілий CLI або сервер |
| `rust-anything rules <repo> --add "<rule>"` | Виправлена вами поведінка, яку зберігає кожен наступний порт |
| `rust-anything map <repo>` | Кожен модуль, його крейт, випадки й останній diff |
| `rust-anything log <repo>` | Кожне вмикання чи вимикання, кожен результат wire, lift і gate, з `rust/audit.jsonl` |
| `rust-anything setup` / `doctor` / `mcp` | Встановлення для агентів, перевірка середовищ виконання, MCP-сервер |
