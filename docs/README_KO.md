## 빠른 시작

이것을 코딩 에이전트에 붙여 넣으세요:

```text
Install Rust Anything with npm i -g rust-anything, then run rust-anything setup. Run rust-anything go -- <slow command of this app> and finish the port until rust-anything gate passes.
```

또는 직접 설치하세요:

```sh
cargo install rust-anything   # 또는: npm install -g rust-anything
rust-anything setup           # Claude Code, Codex, Cursor, Gemini CLI, OpenCode에 추가합니다
rust-anything doctor          # 원본에 필요한 런타임을 점검하고, 각각의 해결 방법을 알려 줍니다
```

> [!WARNING]
> 기록은 원본의 실제 코드를 실행합니다. 복사본에서 작업하고, 서버는 테스트 데이터베이스를 가리키게 하세요.
> `record --sandbox`와 `app record --sandbox`는 네트워크 없이, 저장소는 읽기 전용으로, CPU와 메모리 제한을 걸고 실행합니다 (Linux에서는 bubblewrap, macOS에서는 sandbox-exec; `doctor`가 있는지 확인합니다).

> [!TIP]
> **에이전트:** 설치 단계, 모든 명령, 포팅 흐름은 [rustanything.ai/llms.txt](https://rustanything.ai/llms.txt)를 읽으세요.

## 작동 방식

<p align="center">
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="assets/how-it-works/ko-dark.svg">
    <img src="assets/how-it-works/ko-light.svg" width="880" alt="analyze가 무엇을 포팅할지 계획하고, rust-anything go가 브리지, 기록, 에이전트의 포팅, gate를 기록된 모든 케이스가 일치할 때까지 반복한 뒤, enable이 호출을 Rust로 전환합니다">
  </picture>
</p>

**무엇이 완료인가.** 여러분의 테스트가 아니라 동작입니다. `record`는 생성된 입력과 주어진 입력으로 원본을 실행하고, 각 호출이 반환하고 던지고 출력하는 것을 저장합니다. `gate`가 통과하면 포팅이 완료됩니다: 기록된 모든 케이스가 일치하고, fmt, clippy, `cargo test`, `unsafe` 검사, 스텁 검사, 기록된 답을 포팅 코드에 붙여 넣었는지 보는 검사가 모두 통과해야 합니다. 여러분의 테스트도 함께 실행됩니다.

**여러분의 테스트가 케이스가 됩니다.** `record --from-tests -- npx jest`(또는 `pytest`)는 원본 자체의 테스트 스위트를 실행하고, 그것이 유닛에 하는 모든 호출을 기록합니다. `--pin-clock`은 양쪽의 시계와 난수를 고정하므로, 날짜에 의존하는 코드도 일치할 수 있습니다.

<p align="center">
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="assets/how-it-works-app-dark.svg">
    <img src="assets/how-it-works-app-light.svg" width="880" alt="앱 전체 포팅: analyze가 계획하고, 결정은 여러분이 내리고, app record가 실제 동작을 기록하고, 프런트 도어가 원본 앞에서 Rust를 실행하고, 원본으로 넘어가는 것이 없어질 때까지 유닛을 하나씩 옮긴 뒤, lift가 순수 Rust 앱을 남깁니다">
  </picture>
</p>

**앱 전체: CLI와 서버.** `app record`는 CLI(종료 코드, stdout, stderr, 작성된 파일)를 기록하거나, `--http`와 함께 쓰면 모든 요청에 대한 서버의 응답을 기록합니다. `app front-door`는 `rust/app`을 만듭니다. 진입점을 맡고 아직 포팅되지 않은 모든 것을 원본에 넘기는 Rust 바이너리입니다. `app wire`는 유닛을 하나씩 옮기고, 폴백 비율이 0으로 떨어지는 동안 `app replay`는 100%를 유지해야 하며, `app lift`는 순수 Rust 앱을 남깁니다.

**부수 효과도 셉니다.** 웹훅이나 이메일 보내는 것을 잊은 포팅은 실패해야 합니다. `app record --effects http,smtp`(또는 `--effect-env WEBHOOK_URL=http-url`)는 앱이 나가는 모든 호출과 메일을 기록하는 로컬 대역을 가리키게 하고, `--db-dump "sqlite3 app.db .dump"`는 요청마다 데이터베이스를 기록합니다. replay는 포팅이 똑같이 하는지 확인합니다.

**원본이 계속 바뀐다면?** `app drift`는 원본을 그 기록에 대고 다시 실행해 이제 다르게 응답하는 것을 나열하고, [GitHub Action](install.md#in-ci)은 푸시할 때마다 `gate`를 실행합니다.

**결정은 여러분이 합니다.** 포팅의 동작을 바로잡으면 `rules --add "<rule>"`가 그것을 보관하고, 이후의 모든 에이전트 프롬프트에 포함됩니다. rust-anything이 쓰는 모든 것은 `<repo>/rust/`에 있습니다.

**보고서 또는 마이그레이션, 선택은 여러분의 몫.** `analyze`와 `profile`은 보고만 합니다: 무엇을 포팅할지 순위를 매긴 계획과, 실제 워크로드에서 무엇이 뜨거운지. 일반 명령이므로 보고서에는 토큰이 들지 않습니다. `go`는 한 유닛을 마이그레이션합니다: 가장 뜨거운 함수를 브리지하고, 기록하고, 포팅을 에이전트에 넘긴 뒤, 빌드하고 diff로 비교하고 `gate`를 실행하며, 모든 것이 일치할 때만 켭니다 (TS/JS, Python, PowerShell; `disable`로 다시 끌 수 있습니다).

**한 번 실행에 걸리는 시간.** `go`를 한 번 실행하면 한 유닛을 포팅하며, 에이전트 턴은 최대 `--rounds`번(기본값 3)입니다: 포팅에 한 번, 그 뒤 실패한 diff나 gate마다 한 번. 앱 전체는 유닛마다 한 번씩 실행하므로, 어느 실행 뒤에든 멈출 수 있습니다.

**계획에는 저렴한 모델, 포팅에는 강한 모델.** 계획에는 모델이 필요 없습니다. 포팅에는 아무 에이전트 명령이나 넘기세요: `rust-anything go --agent "claude --model <model>" -- <workload>`.

**에이전트.** `rust-anything setup`은 Claude Code, Codex, Cursor, Gemini CLI, OpenCode에 추가합니다. 다른 MCP 클라이언트는 `rust-anything mcp`를 실행할 수 있고, 스킬은 `npx skills add erkamyaman/rust-anything`로 따로 설치할 수도 있습니다([설치](install.md) 참고).

**검증됨**은 다른 사람이 작성한 실제 코드에서 처음부터 끝까지 포팅했다는 뜻이고, **테스트됨**은 이 저장소의 픽스처 테스트로 다룬다는 뜻입니다. 날짜와 확인 방법이 담긴 모든 실행 기록: [STATUS.md](STATUS.md).

## 명령어

| 명령어 | 하는 일 |
| --- | --- |
| `rust-anything go -- <workload>` | 프로파일링하고, 가장 뜨거운 함수를 브리지하고, 기록하고, 포팅을 에이전트에 넘기고, gate를 통과시키고, 켭니다 |
| `rust-anything analyze <repo>` | 순위를 매긴 마이그레이션 계획: 유닛, 준비도, 위험, 의존성 |
| `rust-anything profile <repo> -- <workload>` | 실제 워크로드에서 무엇이 뜨거운지, 무엇을 포팅하거나 묶을지 |
| `rust-anything bridge <repo> <unit>` | 한 유닛의 바인딩을 담은 Rust 크레이트, 스텁은 `src/port.rs`에 |
| `rust-anything record <crate>` | 원본이 반환하고 던지고 출력하는 것을 기록 (`--inputs`, `--from-tests`, `--pin-clock`) |
| `rust-anything diff <crate>` | 기록된 모든 케이스를 Rust 모듈에 대고 다시 실행 |
| `rust-anything bench <crate>` | 기록된 케이스로 원본과 Rust의 시간을 측정, 브리지 포함 |
| `rust-anything fuzz <crate>` | 양쪽에 새 입력을 넣기: 기록이 다루지 못한 부분 |
| `rust-anything gate <crate>` | 완료의 정의 |
| `rust-anything enable` / `disable <crate>` | 호출자를 Rust로, 또는 다시 원래대로 전환 |
| `rust-anything report <crate>` | `REPORT.md`와 풀 리퀘스트용 카드 |
| `rust-anything app record` / `front-door` / `wire` / `replay` / `lift` / `drift` | CLI나 서버 전체를 포팅 |
| `rust-anything rules <repo> --add "<rule>"` | 여러분이 바로잡은 동작, 이후 모든 포팅에서 유지 |
| `rust-anything map <repo>` | 모든 유닛과 그 크레이트, 케이스, 마지막 diff |
| `rust-anything log <repo>` | 모든 켜기와 끄기, wire, lift, gate 결과를 `rust/audit.jsonl`에서 보여 줌 |
| `rust-anything setup` / `doctor` / `mcp` | 에이전트용 설치, 런타임 점검, MCP 서버 |
